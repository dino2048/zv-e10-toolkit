# 硬件与接线

这条链路需要 RP2040 Pico（树莓派 Pico）、固定接线和电池/复位时序。

## 必需

- ZV-E10；
- RP2040 Pico；
- 470Ω 电阻；
- USB-C 接线；
- 相机电池。

## 引脚

A6/A7 是 USB-C 插座上的数据引脚编号：

- **A7 = D−**；
- **A6 = D+**。

## 接线

| Pico | 相机 USB-C | 说明 |
|---|---|---|
| **GP28** | D−（A7） | 串口数据；Pico 发，相机收；直连 |
| **GP27** | **470Ω → D+（A6）** | 复位 |
| 5V | VBUS | 5V 连在一起 |
| GND | GND | 共地 |

**CC1 和 CC2 连接在一起，经 5.1kΩ 下拉到 GND。**

- 注入期间相机 USB-C 接 Pico，不接电脑；
- D− 使用 open-drain，不要 3.3V 推挽；
- GP28 和 GP27 的功能不能互换。

如果不行，翻转 USB-C 方向再试。

## 电池与复位

- 电池插着，相机正常开机；
- 脚本先开载波，再发 GP27 10 µs 低脉冲复位相机，然后整组重放；
- **有复位后不需要拔电池**；拔电池冷启动是旧的 v7 方法，当前不用。

## 换线到电脑

- payload 检测 VBUS 低 → 高；看到长闪后把相机 USB-C 从 Pico 移到电脑；
- Pico 5V 和 Mac 5V 会在相机 VBUS 上顶在一起，Pico 可能从 Mac 掉线，不影响已经在运行的 payload。

## LED

- 一次长闪（0.4 s）：payload 活着；
- 短脉冲计数：USB 时钟/PHY → DWC3 → EP0 配置 → 等主机；
- 之后每 2 秒一次短脉冲：在等主机枚举；
- 停在第 N 个短脉冲：对应步骤没有返回。

## 停止 / 恢复正常启动

从仓库根目录：

```sh
python3 fastboot/pico/reset_only.py --port /dev/cu.usbmodemXXXX
```

发一次 GP27 复位、关闭载波，相机回到正常启动，不用拆电池。也可以直接断电/取电池：
payload 在 SRAM，易失。

## 边界

- 这是 BootROM 串口启动，不是运行时漏洞；需要专用接线和复位时序。
- 只写 SRAM；不写 eMMC、SD 或 OTP。
